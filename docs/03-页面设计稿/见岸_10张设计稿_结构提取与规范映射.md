# 见岸 · 10 张设计稿结构提取与规范映射

> **设计稿是实例，不是规范。** 唯一设计权威是 `02-设计系统/见岸_Quiet_Horizon_动态Google_Stitch_DESIGN.md`（下称 DESIGN.md）。
>
> 本文件从 10 张实例稿中提取三样可复用的东西——**页面区块结构、组件构成、文案**——并逐项标出实例稿的视觉表现与 DESIGN.md 规范冲突的地方。冲突处一律按 DESIGN.md 实现。

## 1. 取用边界

| 从设计稿取用 | 不从设计稿取用（按 DESIGN.md） |
|---|---|
| 页面有哪些区块、区块从上到下的顺序 | 色彩、字号、间距、圆角、阴影 |
| 每个卡片内部由哪些元素构成、信息层级 | 图形与插画语言、装饰质感 |
| 全部文案（标题、数值、按钮、标签、空态提示） | 数据可视化形态的选择 |
| 页面之间的跳转关系与导航归属 | 动效、状态矩阵、响应式、无障碍 |

设计稿里的数值（`78`、`+12 分`、`92`）是占位示例，不是产品规则；`04` 的三步任务、`07` 的三条归因也是示例内容，真实内容由算法产出。

**DESIGN.md 有规范但无实例稿的 5 屏**：§11.1 Onboarding、§11.5 Practice Hub、§11.11 Mock Exam、§11.12 Essay 申论、§11.13 Interview 面试。这 5 屏按 DESIGN.md 正文规格实现即可，不缺依据。

底部导航 5 项 **今日 / 训练 / 教练 / 进展 / 我的** 与 DESIGN.md §7.14 完全一致，无冲突。实例稿中 `03` 把 Tab3 改名「提分诊断」、`09` 把 Tab4 改名「选岗」，是实例稿的占位处理，不采纳——两页按上表挂在子路由，标签固定。

## 3. 必须按 DESIGN.md 重新表达的视觉项

实例稿在这些地方与 DESIGN.md 直接冲突，**以 DESIGN.md 为准**：

| 实例稿画法 | DESIGN.md 规范 |
|---|---|
| 蓝色体系（深蓝 `#1B386F`、亮蓝 `#4E95EB`、冷蓝底 `#F8F9FC`） | 青绿 `primary #2B6367`，暖雾白 `canvas #F7F9F8`，稀缺曙光铜 `dawn #C88E56` |
| 高饱和语义色（`#E96159` / `#51B98A` / `#FD9F4E`） | 低饱和 `error #B85A50` / `success #4F7B68` / `warning #B67A43` |
| 缺口圆环 + 端点圆珠作为分数仪表（10 处） | §13 谨慎使用 donut / gauge；Today 的核心表达是 §7.4 Focus Card + Horizon Focus Reveal，不是环形仪表 |
| `78/100` 综合能力评分、5 模块 `74/81/58/67/72` 百分制 | §4 禁伪精确；§11.4 明确用 ranked opportunity list / horizontal contribution bar / sparkline / 置信区间，而不是给每个模块打分 |
| `08` 五维雷达图 | §13 默认避免 radar 作主诊断，改 small multiples 或横向贡献条 |
| 玻璃球体、玻璃阶梯、六边形徽章、图标底座遍布内容层 | §6 Functional Glass 仅限 Z3 功能层；§2.4 只用 雾 / 地平线 / 岸光 三个意象 |
| 3D 机器人形象作 AI 头像与底栏 Tab3 图标 | §2.5 禁直白拟人符号；教练是能力层不是吉祥物形象 |
| 成就六边勋章、Lv.4 等级徽章 | §9 弱化游戏化装饰 |

换句话说：**实例稿的骨架可用，皮不可用。** 例如 `01` 的"问候 → 状态卡 → 单点突破口 → 四入口 → 金句条"这个顺序照搬；但状态卡不做成"圆环 + 78/100"，而做成 DESIGN.md 的 Focus Card（micro-label + horizon indicator + 1–2 行核心判断 + 一句证据摘要 + 主 CTA + "为什么"），首次进入播 420–560ms Horizon Reveal。

## 4. 逐页区块骨架

数值与文案为实例稿原文，可作为文案初稿；结构顺序建议保留。

**01 今日首页**：顶栏（logo + 日期 + 头像）→ 问候语「早安，追光者 / 每一步清晰的努力，都会把你带到岸边。」→ 今日备考状态（核心判断 + 状态短语「稳步向岸」+ 「状态解读」入口）→ 今日最值得解决（蓝色小字「今天最值得解决:」+ 主标题「资料分析速度」+ 一句证据 + 「+12 分」可提升空间 + 「高影响力」chip）→ 四入口 2×2（AI诊断「3项优势 · 2个待突破点」/ 今日处方「3个任务 · 预计 120 分钟」/ 训练进度「本周已完成 12/18 任务」/ 晚间复盘「复盘可提升 23% 学习效率」）→ 金句条。

**02 上传成绩**：标题组 →三步 Stepper（上传 / 解析 / 校对）→ 多图上传网格（含「+ 继续添加 / 支持图片 / 截图」与「支持 JPG / PNG，单张不超过 20MB」）→ 识别进度（「AI 识别中... / 正在解析图片中的成绩信息」+ 65%）→ 识别结果字段网格（每字段带可信度标记：可信 / 疑似不完整）→ AI 初步解读（2 条项目符号）→ 主 CTA「确认并生成诊断」+ 脚注「生成后将消耗 1 次诊断机会」。

注：DESIGN.md §11.3 要求识别阶段**不用假线性进度条**，改阶段文案「正在识别 → 正在核对 → 等你确认」。实例稿的 65% 进度条不采用。

**03 提分诊断**：标题组 + 「诊断设置」→ 最大提分机会（「当前最大提分机会:」+「资料分析速度」+ 一句依据 + 「+12 分潜力」+「查看依据」+ 置信度「高 / 基于 128 道题数据」）→ 模块表现总览（五模块，按 §11.4 改为 ranked list / 贡献条）→ 优势卡（「保持优势」chip）+ 瓶颈卡（「优先突破」chip）→ 证据卡（「近期趋势（近5次练习）」正确率实线 + 用时虚线）→ 建议动作（「专项提速：资料分析」+ 三条勾选项 + 「立即开始」）→ 底部提示「诊断会随练习持续更新，建议每周重新诊断。」

**04 学习处方**：标题组 → 处方总览（预计总时长「95 分钟」+「调整计划」）→ 今日任务清单（3 条：资料分析限时训练 40 分钟 / 错因修复 30 分钟 / 申论素材积累 25 分钟，各带优先级 chip 与「目标：…」）→ 「为什么是这三步？」三条解释 → 主 CTA「开始执行（95 分钟）」。

**05 专项训练**：会话条（模块 chip + 难度 chip + 题型 chip + 计时 `00:08:36` + 暂停 + 题目进度 `4 / 15`）→ 题干与材料（可含图表、表格）→ 设问 + A/B/C/D 选项 → 工具条（AI提示「智能点拨思路」/ 标记「加入错题本」/ 稍后复盘「待会再回来」）→ 主 CTA「提交本题」。

**06 练习复盘**：标题组 + 练习选择下拉 → 总览三分栏（正确率 `72%` + 平均用时 `18 分 32 秒` + 答题质量 `B+`，各带环比）→ 主要问题（「错误主要来自 读题过慢」+ 一句归因）→ 四卡（错因分类 / 易错题 / 时间分布 / 修复建议）→ 题目表现（筛选 chip 全部 / 错误 / 收藏 + 逐题行：序号 + 对错 + 题型 chip + 题干 + 正确答案 vs 你的答案 + 用时 + 「查看解析」）→ 底部 CTA「加入修复计划」。

**07 AI教练**：教练身份头 + 状态 chip → 用户提问气泡 → AI 回答（归因列表，每条含「高于/低于同水平考生 xx%」+ 可展开）→ 证据入口条 → 方案卡 + 快捷操作按钮（生成专项训练 / 调整今日处方 / 查看证据）→ 输入栏「有问题，尽管问我」→ 免责声明「AI建议仅供参考，请结合自身情况决策」。

DESIGN.md §11.8 补充要求：顶部带 context chip，3 个动态建议问题，回复结构为 结论 → 证据 → 建议 → 行动按钮，streaming 按语义块而非逐字打字机。

**08 进展周复盘**：周范围顶栏（第 20 周 / 5月20日–5月26日）→ 周趋势（总体趋势「稳步向上」+ 状态评分 + 6 周折线 + 洞察条）→ 本周最有效动作 → 能力趋势（雷达改为 small multiples）→ 学习节奏（任务完成率 + 学习时长 `12 h 40 min` + 练习题数 `386 题` + 正确率）→ 下周建议 3 条 → 金句条。DESIGN.md 拆为 §11.9 Progress 与 §11.10 Weekly Review 两屏，Weekly Review 有 560–700ms 的 Signature 转场。

**09 智能选岗**：标题组 + 「选岗指南」→ 筛选区（报考省份 / 招考系统 / 成绩区间 / 竞争压力 + 搜索 + 更多筛选）→ 最优推荐岗位（匹配度 + 岗位名 + 属性标签 + 竞争压力 / 进面概率 / 预估进面分 + AI 脚注）→ 岗位列表项（序号 + 匹配度 + 标签 + 招录人数 / 报名比 / 进面分 / 进面概率 + 「加入对比」）→ 对比操作条「已选 0/3 个岗位进行对比」→ AI 选岗分析。DESIGN.md §11.14 要求 dense professional list + expandable evidence panel，不用大图商品卡——实例稿符合。

**10 我的**：顶栏（logo + 通知 + 扫码）→ 用户档案卡（昵称 + 等级 + 签名 + 四统计：连续学习 `128 天` / 累计学习 `856 小时` / 累计刷题 `2796 道` / 综合能力评分）→ 学习档案四入口（我的笔记 / 我的收藏 / 错题本 / 模拟卷记录）→ 我的目标（进度 + 考试名 + 倒计时 + 阶段进度）→ 近期成就 → 设置列表（订阅与权益 / 数据与隐私 / 设置）。DESIGN.md §11.15 额外要求 AI 记忆可见可编辑可删除。

## 6. 实例稿的内容错误

以下三处是稿件错误，不要照抄：

1. `06_练习复盘` 下拉写「高三数学 · 函数专题训练」，三道题是 K12 高中数学（`f(x)=ln(x+1)` 定义域、`f(3)` 求值、单调区间）。应替换为行测题型。
2. `06` 第 3 题题干含未渲染的 LaTeX 残留 `\frac[1/x-1`。
3. `10_我的` 的「我的目标」写「2025 法律职业资格考试」，应替换为公考目标。

## 7. 实例稿未覆盖但功能清单要求的模块

对照 `04-功能规格` 的 388 个功能点，实例稿没有实例、但 DESIGN.md 有规格可依的：申论（功能清单 29 条 → DESIGN.md §11.12）、面试（22 条 → §11.13）、站内整卷模考（18 条 → §11.11）、Onboarding（→ §11.1）、Practice Hub（→ §11.5）。

三者都薄的：**会员与支付**（功能清单 9 条，DESIGN.md 无付费屏，实例稿只有一行入口「见岸 Pro 会员」和「消耗 1 次诊断机会」）。这是唯一需要从零补规格的模块。

全局态（空 / 错 / 离线 / 弹窗 / 深色）实例稿无稿，按 DESIGN.md §17 夜间主题与 §18 四态实现；注意 §17 只给了 8 个深色色值，缺 border 与四个语义色的深色对应值，需补齐。
